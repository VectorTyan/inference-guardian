# 版本记录

## 0.29.0

按三批完成服务包目录迁移。containers 负责 Docker 访问与容器契约，observability 负责审计和日志，health 负责探针及故障证据，control 负责 Controller 配置、拓扑和恢复编排，agent 集中节点服务、管理客户端与 Agent 日志。根目录的原公开模块作为兼容入口，新旧路径共享同一份实现，保留公开类型身份、依赖替换、序列化路径和日志分类。CLI、配置与状态格式及恢复行为沿用既有契约。

迁移前 422 项回归通过，三批分别通过 429、430、431 项。新增 9 项兼容测试覆盖 16 个模块的原导出、签名、类型身份、新旧导入顺序、重新加载、依赖替换及导入副作用。全部迁移实现的业务语法树与基线一致。88 个源码文件通过 Python 3.7 语法检查，87 个独立导入检查通过，未发现循环依赖。源码包包含实现子包和原兼容入口，现场材料与测试继续放在 Git 忽略的 local/。真实 Docker、SSH 和 NPU 故障恢复需在部署端验收。

## 0.28.1

提取 Agent 的成功动作回执查询，统一按容器、恢复组、代次和启动周期关联 stop/start。Controller 将多组遍历、单组观测、canary 结果接纳、进程诊断及 observe 恢复建议分开处理，并复用故障计数清理逻辑。公开调用签名、CLI、配置与状态格式、恢复范围、动作顺序和未知结果对账规则继续使用既有契约。

重构前 410 项回归通过，补充 12 项行为测试后 422 项全部通过。新增覆盖同节点多容器回执、同节点多恢复组状态隔离、同节点动作串行、跨节点失败收敛、canary 结果作废和各类故障计数清理。Python 3.7 语法、独立导入及循环依赖检查通过。测试材料保存在本地 local/validation。服务层已有的多组表达作为后续扩展基础，标准安装清单仍使用现有两节点和四节点场景。真实 Docker、SSH 和模型恢复需在部署端验收。

## 0.28.0

源码、示例目录清单和部署输入分开维护。默认打包使用公开示例，指定 --delivery-dir 时从外部目录读取配置及基础镜像并将产物写入该目录的 dist。打包前在暂存目录验证所有场景。安装参数、守护服务接口、恢复与事务协议沿用既有格式。维护者可将站点资料、测试和历史归档集中放入 Git 忽略的 local/。两条配置路径各通过 410 项离线回归，现网配置对照覆盖四套示例的 28 份 JSON 及 12 个节点身份和配置指纹。真实节点升级仍须在部署端验收。

内置配置集中在宿主工具的 presets 模块，原导入路径和类型保留。命令传输模块独立识别 seccomp 启动错误，探测、比较和事务处理继续使用原有入口。公开 ID 适用于新部署，私有部署升级需沿用原发行线。

离线验证使用标准库测试、临时文件和节点替身，分别核对原配置行为与公开示例。真实 Docker、SSH 和推理服务须由部署方验收。
